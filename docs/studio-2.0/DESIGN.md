# 스튜디오 2.0 — 설계 대안 비교와 확정안

목표 흐름: **레시피 입력 → 웹 안에서 AI 대본 생성 → 장면·자막 편집 → 전문가 검수·승인 → 영상·블로그 생성 → 최종 확인 → 플랫폼 게시**

최종 사용자는 요리 연구자(이희재)다. Claude Code나 터미널을 직접 다루지 않는다.

비용·가격 수치는 2026-11-03에 확인한 공개 가격 기준 **추정치**다. 환율은 1 USD ≈ 1,450원으로 계산했다.

## 1. 웹 안에서 AI 콘텐츠 생성

### 1.1 대안 비교

가정: 대본 1회 생성 = 입력 약 2,000 토큰(원본 레시피 + 규칙), 출력 약 3,000 토큰(사고 과정 포함). 한 달에 콘텐츠 16편, 편당 재생성 3회 = 약 50회.

| 방식 | 회당 비용(추정) | 월 비용(50회) | 한국어 품질 | 구현 난이도 | 비고 |
| --- | --- | --- | --- | --- | --- |
| 템플릿(현행) | 0원 | 0원 | 정형적 | 완료 | 항상 유지 (API 없이도 제작) |
| 무료 AI 채팅 붙여넣기(현행) | 0원 | 0원 | 높음 | 완료 | 수동 복사 필요 |
| Claude API — Haiku 5.5 ($0.10/$0.50 per 1M) | 약 2원 | 약 100원 | 양호 | 중 | JSON 구조 보장(structured outputs) |
| Claude API — Sonnet 5.5 ($2/$10) | 약 45원 | 약 2,300원 | 높음 | 중 | |
| Claude API — Opus 5.5 ($4/$20) | 약 90원 | 약 4,500원 | 가장 높음 | 중 | Anthropic 기본 권장 모델 |
| Gemini API | 모델별 상이 | Google AI Pro에 월 약 $10 Cloud 크레딧 포함(활성화 필요) | 높음 | 중 | 크레딧 초과분은 청구 |
| 로컬 모델(Ollama 등) | 0원 | 0원(전기료) | 7B급은 한국어 대본 품질 낮음 | 중상 | CPU에서 회당 수 분, PC 상시 실행 |

**구독과 API는 결제가 별개다.** ChatGPT Plus·Gemini Pro 구독료로는 API를 쓸 수 없다(Gemini Pro는 Cloud 크레딧 혜택만 있음).

### 1.2 확정안

1. **생성기 인터페이스를 하나로** 둔다: `ScriptGenerator { generate(recipe, options, signal) → 후보 대본 + 사용량 }`.
   - 구현체: `template`(현행), `paste`(현행), `claude`(신규 1순위), `gemini`(신규 2순위, 선택).
   - 프롬프트 작성·응답 검증은 `recipe-core`(순수 함수), API 호출은 `apps/studio/server`(비밀키 보관)에 둔다.
2. **첫 실제 생성 경로는 Claude API**로 한다. 공식 SDK(`@anthropic-ai/sdk`)와 structured outputs(`output_config.format` JSON 스키마)로 대본 구조를 보장한다. 모델은 설정에서 고르고, 위 비용표를 화면에 보여 준다. 기본 모델은 사용자 승인 사항이다.
3. **API 키는 서버의 `.env`에만** 둔다. 브라우저·로그·DB·Git에 남기지 않는다. 화면에는 "연결됨/안 됨"만 표시한다.
4. **원본 위반 차단(강화)**: AI 결과는 `ScriptSchema` 검증 → `enforceSourceData`(재료 카드 원본 고정, 순서 카드도 원본 문장으로 고정) → `checkScript`를 거친다.
   - `error` 등급(원본에 없는 분량, 재료·순서 변경)이 하나라도 있으면 **"고쳐야 승인 가능" 상태로 저장하고 승인 버튼을 막는다.** 지금처럼 확인창으로 넘어가지 못하게 한다.
   - 사람이 직접 고쳐 오류가 0이 되면 승인할 수 있다.
5. **장면 재생성**: 한 장면만 다시 쓰게 할 수 있다(장면 id + 앞뒤 문맥 + 원본). 결과는 새 대본 버전이 되고 승인은 풀린다.
   - 음성은 이미 **바뀐 대사만** 다시 만든다(줄 단위 캐시, 이번에 키 결함 수정).
   - 영상은 1단계에서는 전체를 다시 렌더한다. 장면 단위 영상 캐시(장면별 렌더 → 이어 붙이기)는 3D 상태·오디오 이음새 검증이 필요해 후속 단계로 둔다. 대신 **브라우저 미리보기는 렌더 없이 즉시** 바뀐다(현행).
6. **작업 관리**: 모든 오래 걸리는 일(AI 생성, 음성, 렌더, 게시)을 `jobs` 표로 통일한다.
   - 상태: 대기 / 진행 중 / 완료 / 실패 / 취소됨. 진행률, 사용자용 오류 문장, 개발자용 상세(숨김).
   - 취소: AI·음성은 `AbortSignal`, 렌더는 Remotion `cancelSignal`.
   - 재시도: 같은 입력으로 새 작업을 만든다(자동 재시도는 일시적 오류만, 최대 2회).
7. **예산 한도**: 월 한도(원)를 설정한다. 생성 전 예상 비용을 보여 주고, 한도를 넘을 요청은 시작하지 않는다. 실제 사용량(API가 돌려주는 토큰 수)을 기록해 월별 합계를 보여 준다.

## 2. 인스타그램 공식 게시

> Meta 개발자 문서(developers.facebook.com)는 이 작업 세션의 네트워크에서 열리지 않아, 검색 결과와 기존 지식으로 정리했다. 구현 착수 전에 해당 도메인을 허용하고 아래 ⚠ 표시를 공식 문서와 대조한다.

### 2.1 로그인 방식

| 방식 | 필요 조건 | 판단 |
| --- | --- | --- |
| **Instagram API with Instagram Login** | Instagram 프로페셔널 계정(비즈니스/크리에이터). 페이스북 페이지 불필요 | **채택** — 어머니 계정만 연결하면 됨 |
| Instagram API with Facebook Login | 페이스북 페이지와 연결된 프로페셔널 계정 | 보류 |

- 권한 ⚠: `instagram_business_basic`, `instagram_business_content_publish`
- 어머니 계정을 앱의 **테스터**로 등록하면, 앱 심사 없이 그 계정에 대해서만 쓸 수 있다(개발 모드) ⚠. 다른 사용자 계정 지원은 앱 심사가 필요하므로 별도 단계.
- 토큰: 짧은 토큰 → 장기 토큰(약 60일) 교환, 만료 전 자동 갱신 ⚠. 서버 DB에 **암호화(AES-256-GCM, 키는 `.env`)**해 저장.

### 2.2 게시 흐름

```
① 사전 검사 → ② 컨테이너 생성 → ③ 처리 상태 확인 → ④ 사용자 최종 확인 → ⑤ 게시 → ⑥ 결과 기록
```

1. **영상 규격 자동 검사**(내장 ffprobe): MP4, H.264 + AAC, 9:16(1080×1920), 300MB 이하, 길이 제한 ⚠, 프레임레이트. 현재 출력(1080×1920, H.264/AAC, 약 37~43초)은 통과할 것으로 예상.
2. **컨테이너 생성**: `POST /{ig-user-id}/media` with `media_type=REELS`, `caption`, 그리고 영상 전달 방식 둘 중 하나:
   - **(a) 재개 가능한 업로드**(`upload_type=resumable` → `rupload` 호스트로 파일 전송): 공개 저장소가 필요 없다. Instagram Login 경로에서 지원되는지 ⚠ 확인.
   - **(b) `video_url`**: Meta가 내려받을 수 있는 공개 HTTPS 주소가 필요하다. 아래 2.3.
3. **상태 확인**: `GET /{container-id}?fields=status_code`를 주기적으로 조회한다. `FINISHED`가 되면 다음 단계로 간다. `ERROR`·`EXPIRED`이면 사용자에게 알린다.
4. **사용자 최종 확인**: 영상·설명문·해시태그·계정 이름을 한 화면에 보여 주고 "인스타그램에 올리기"를 직접 누르게 한다. 승인되지 않은 대본으로 만든 영상은 이 화면에 들어오지 못한다.
5. **게시**: `POST /{ig-user-id}/media_publish` with `creation_id`.
6. **기록**: 게시물 ID, permalink(URL), 게시 시각, 사용한 렌더 번호를 저장한다.

### 2.3 Meta가 내려받을 임시 HTTPS 영상 주소 (2.2-(b)일 때)

| 방안 | 비용 | 판단 |
| --- | --- | --- |
| 스튜디오 자체가 터널(Cloudflare Tunnel 등)로 HTTPS 공개 + **만료되는 서명 주소**(`/public-media/<서명>.mp4`, 15분) | 0원 | **1순위** — 5장 배포안 A와 같은 터널 재사용 |
| Cloudflare R2 등 객체 저장소 + 서명 URL | 무료 한도 내 0원 | 2순위 |
| 영구 공개 폴더 | 0원 | 사용 안 함(유출 위험) |

### 2.4 오류·중복 방지

- `publications` 표: (콘텐츠, 렌더, 플랫폼)마다 1건. 상태 = 준비 / 업로드 중 / 처리 중 / 확인 대기 / 게시 중 / 게시됨 / 실패.
- **이미 "게시됨"이면 같은 렌더는 다시 올릴 수 없다.** 다시 올리려면 사용자가 "다시 게시"를 따로 확인해야 한다.
- `media_publish`는 자동 재시도하지 않는다. 응답을 못 받았으면 최근 게시물을 조회해 실제로 올라갔는지 먼저 확인한다.
- 게시 한도: 24시간에 API 게시 100건(공식 문서 확인됨). `content_publishing_limit` 조회로 화면에 남은 수를 보여 준다.
- 토큰 만료·권한 철회: "인스타그램 연결이 끊겼어요. 다시 연결해 주세요" 안내 + 다시 연결 버튼.

### 2.5 검증

- **모의 통합 테스트**: Graph API를 흉내 내는 로컬 서버로 컨테이너 생성 → `IN_PROGRESS` → `FINISHED` → 게시, 오류·만료·중복 시나리오 전부.
- **실제 통합 테스트**: 어머니 테스트 계정(또는 비공개 테스트 계정)에 1건. **사전 승인 후에만** 실행한다.

## 3. 네이버 블로그

네이버 블로그 글쓰기 API는 종료됐다. **자동 발행은 구현하지 않는다.** 비공식 자동화(브라우저 조작 등)는 약관·보안·안정성 문제로 쓰지 않는다.

구현할 것:

| 기능 | 내용 |
| --- | --- |
| 원고 생성 | 제목, 본문(묶음별 재료·순서·원리·팁), 이미지 자리, 해시태그 (현행 확장) |
| 수정 가능한 미리보기 | 제목·본문·태그를 화면에서 고치고 저장(원고 버전) |
| 복사 | 서식 복사(HTML), 일반 글 복사, 제목·태그 따로 복사 (현행) |
| 이미지 내려받기 | 커버·썸네일·레시피 카드 개별 내려받기 + 묶음 |
| 편집기 열기 | 블로그 글쓰기 화면을 새 창으로 열기(블로그 ID 설정) |
| 게시 후 URL 등록 | `blog.naver.com/{id}/{글번호}` 형식 확인 후 저장 |
| 일관성 검사 | 영상 대본·블로그·SNS 설명의 재료·분량·핵심 팁이 서로 같은지 검사(아래 4) |

### 4. 영상·블로그·SNS 일관성 검사 (`publishing/consistency.ts`)

- 비교 기준은 항상 **원본 레시피**다.
- 블로그: 원본 재료·분량이 전부 있고, 원본에 없는 분량이 없어야 한다.
- 영상 대본: 기존 `checkScript` 결과에 오류가 없어야 한다.
- SNS 설명: 원본에 없는 분량·주장이 없어야 하고, "검토한"은 승인 후에만 들어간다.
- 결과는 게시 확인 화면에 "세 곳 내용 일치 ✓"로 보여 주고, 불일치 시 게시를 막는다.

## 5. 웹서비스 배포

### 5.1 대안 비교

| 항목 | A. 하이브리드 (PC에서 생성, 웹에서 사용) | B. 전부 클라우드 |
| --- | --- | --- |
| 구성 | 어머니(또는 가족) PC에서 스튜디오·VoiceStudio 실행 + HTTPS 터널로 외부 접속 | 서버에서 AI·음성·렌더까지 처리 |
| 월 비용(추정) | 0원 (터널 무료, 도메인 선택 시 연 1~2만 원) | 소규모라도 월 수만~수십만 원. CPU 서버 상시 운영은 월 약 15~30만 원, GPU를 쓸 때만 켜는 방식은 사용량 따라 월 수만 원 + 구성 난이도 큼 |
| PC 상시 실행 | **필요**(제작·접속하는 동안) | 불필요 |
| 개발 난이도 | 낮음 — 기존 코드 거의 그대로 | 높음 — 모델(약 5GB) 포함 컨테이너, GPU 서버, 작업 대기열, 저장소 |
| 속도 | PC 성능에 좌우(GPU 있으면 빠름) | GPU 쓰면 빠름 |
| 보안 | 터널 + 로그인 필수. 데이터가 집 PC에 있음 | 서버 보안·비밀키 관리 필요 |
| 장애 복구 | PC 꺼지면 중단 → 켜면 재개, `data/` 백업 필요 | 서버 장애 대응·백업 체계 필요 |
| 기존 코드 재사용 | 거의 100% | 렌더·음성 실행 환경 재구성 필요 |

### 5.2 확정안 (단계적)

1. **A1 (먼저)**: PC 실행 + **로그인** + **HTTPS 터널**(Cloudflare Tunnel 또는 Tailscale). 어머니가 다른 PC·휴대폰 브라우저에서 접속. 비용 0원. 공개 전 사용자 승인 필요.
2. **A2 (필요 시)**: 화면·DB를 작은 클라우드 서버로 옮기고, 무거운 일(음성·렌더)은 집 PC의 "작업자"가 가져가서 처리. PC가 꺼져 있어도 목록·검수·게시 기록은 볼 수 있다.
3. **B (성과 확인 후)**: 제작량이 늘고 예산이 생기면 음성·렌더를 클라우드 GPU로 옮긴다.

### 5.3 보안 기준 (A1부터 적용)

- 로그인 필수: 관리자(개발자)·연구자 2계정, 비밀번호는 scrypt 해시, 세션 쿠키 `HttpOnly; Secure; SameSite=Lax`, 로그인 시도 제한.
- 상태 변경 요청에 CSRF 방지, 업로드 크기·형식 제한(현행 유지).
- 비밀(AI 키, Meta 앱 비밀, 토큰 암호화 키)은 `.env`에만. 화면·로그·ZIP·Git에 나오지 않게 테스트로 확인.
- 터널은 스튜디오 포트만 노출. VoiceStudio(3900)는 외부에 열지 않는다.

## 6. 화면(UI/UX) 기준

주요 화면: **콘텐츠 목록 · 새 콘텐츠 · 대본 검수 · 영상 미리보기 · 블로그 미리보기 · 게시 관리**

- 쉬운 말: "렌더"→"영상 만들기", "API"·"토큰" 같은 말은 설정 화면 밖에서 쓰지 않는다.
- 오류는 한 문장 안내 + 할 일 버튼("다시 시도", "인스타그램 다시 연결"). 상세 기록은 "자세히" 안에 숨긴다.
- 진행 표시: 단계 이름 + 막대 + 남은 시간 예상, 취소 버튼.
- 상태 색 구분: 입력 중(회색) / 검수 대기(노랑) / 승인됨(초록) / 게시됨(남색) / 오류(빨강). 승인 전 화면에는 "승인 전 — 게시할 수 없어요"를 항상 표시.
- 게시 전 최종 확인: 영상 재생, 설명문, 계정, 일관성 검사 결과, "공개 게시됩니다" 문구를 한 화면에. 확인 체크 후에만 버튼 활성화.
- 중복 방지: 게시 버튼은 한 번 누르면 잠기고, 게시됨이면 사라진다.
- 큰 글씨·큰 버튼, 휴대폰 화면에서도 검수·승인 가능.
