## 2. 핵심 설계 결정

### 2.1 후보 3가지 (`recipe-core/src/candidates.ts`)
- 연출 유형 6종 중 **이 레시피 자료로 만들 수 있는** 유형을 점수순으로 보고, 다음을 모두 만족하는 3개를 고른다: **연출 유형이 서로 다름 · 훅 유형이 서로 다름 · 첫 화면 연출이 서로 다름.**
- 각 후보: 제목, 첫 대사, 첫 화면 설명, 핵심 장면 3개 요약, 길이 예상, 추천 이유, 검수 주의점, 완성 대본.
- "다른 후보 보기": 이미 보여 준 (연출, 훅) 조합을 빼고 다시 고른다. 남은 조합이 없으면 그렇게 알린다.
- AI(유료 API) 후보는 승인 후 같은 자리에 붙인다. 그때도 같은 검증(원본 분량·순서)을 거친다.

### 2.2 미리보기와 최종 렌더 분리 (비용 관리)
| | 후보 미리보기 | 검수용·최종 영상 |
| --- | --- | --- |
| 만드는 곳 | 브라우저 (즉시) | 서버 (음성 생성 + 3D 렌더, CPU PC에서 20~30분) |
| 음성 | 없음 (자막·예상 길이) | 맛조수 목소리 |
| 비용 | 0원 | 0원(전기·시간) — 한 번에 하나만 |
| 언제 | 후보 3개 모두 | 고른 후보 1개만 |

### 2.3 승인 전 "검수용 제작" 허용, 내보내기·게시는 승인 후
- 흐름(5 → 7)에 맞춰 **고른 후보는 승인 전에 영상까지 만든다.** 연구자는 대본뿐 아니라 실제 영상을 보고 승인한다.
- 검수용 영상에는 거짓이 될 문구를 넣지 않는다: 서명 카드는 이름·직함·연구소만 쓰고 "검토했습니다"를 쓰지 않는다. 그래서 **승인 후 다시 렌더하지 않아도 된다.**
- **ZIP 내려받기, Instagram 게시, 네이버 발행 기록은 "그 영상의 대본 버전 = 승인된 버전"일 때만** 가능하다. 승인 후 대본을 바꾸면 승인이 풀리고 영상도 다시 만들어야 한다(기존 원칙 유지).
- "검토한" 문구는 승인 후 게시 문구(SNS 설명)에만 들어간다(기존 `brandDescription`).

### 2.4 승인 차단 (스튜디오 2.0 계획 1.5)
- `checkScript` 오류(원본에 없는 분량, 재료·순서 변경)가 하나라도 있으면 승인 API가 거절한다. 지금은 확인창만 뜬다.

### 2.5 매체별 표현
- Instagram 설명: 후보의 첫 대사로 시작 → 한 줄 팁 → 저장·보내기 이유 → AI 고지 → 해시태그.
- 블로그: 같은 원본 레시피, 문체 후보 2개(예: 전문가 조리 노트형 vs 생활 요리 이야기형). 연구자 답변 없는 칸은 "답변 대기".
- 연구자 실제 경험(답변·확인됨) / 원본 레시피 / 검수 필요 초안(원리·팁 문장에 "검수 필요" 표시가 있는 것, 엔진이 만든 연출 문장)을 화면에서 색으로 구분한다.

### 2.6 게시 기록 (`publications` 표)
- 항목: 플랫폼(instagram·naver·youtube), 영상(render) 번호, 대본 버전, 상태(준비·예약·게시됨·실패), 예약 시각, 게시 주소, 게시 시각, 성과(수동 입력), 메모.
- 같은 렌더·같은 플랫폼으로 "게시됨"이 이미 있으면 다시 기록하려면 확인이 필요하다(중복 방지).
- Instagram 실제 게시는 Meta 앱 연결 승인 전까지 **"연결 안 됨"** 으로 막고, 사용자가 앱에서 직접 올린 뒤 주소를 등록하는 방식만 연다.
- 성과(건너뛰기 비율, 평균 시청 시간, 저장, 보내기)는 사용자가 인사이트 화면을 보고 입력 → 연출·훅별로 모아 다음 후보 추천 이유에 보여 준다.

## 3. 이번 작업 범위 (승인 불필요)

1. 후보 3개 생성·미리보기·선택·다시 보기 (화면 포함)
2. 선택 → 검수용 영상 제작(승인 전), 블로그 문체 후보 2개 비교·선택, 후보 첫 대사 SNS 문구
3. 승인 차단 규칙, 검수 화면 보강, 내보내기는 승인 후
4. 게시 기록·성과 입력, 네이버 반자동(이미지 내려받기·글쓰기 열기·주소 등록)
5. Instagram: 게시 기록·예약 상태와 "연결 안 됨" 표시까지. **실제 API 연결은 승인 후**

검증: 호두정과 파일럿 A·B·C가 후보 3개로 그대로 나오는지, 고른 후보의 파일럿 영상으로 검수→승인→내보내기→게시 기록 흐름이 이어지는지 브라우저로 확인한다.

추가로 막은 것: 렌더 폴더의 ZIP·원고 파일을 주소로 직접 받는 길(이제 403). 내보내기는 승인된 최신 버전만.

### 호두정과 파일럿으로 한 실제 흐름 점검 (브라우저, `apps/studio/e2e/user-flow.e2e.cjs`)

1. 파일럿과 같은 입력 → 후보 3개가 **A 문제 해결형 · B 캐릭터 코미디형 · C 요리 과학 실험형**으로 나옴
2. "다른 후보 3개 보기" → 전후 비교형·감각 중심형 등 다른 유형
3. C 선택 → 대본 v1 → 이미 만든 파일럿 C 영상을 검수용 영상으로 연결
4. 블로그 후보 2개 중 "전문가 조리 노트형" 선택
5. 승인 전 ZIP 409 → 체크리스트 승인 → ZIP 200
6. 인스타 주소 기록 → 네이버는 답변 대기 칸 때문에 거절 → 답변 3개 + 본인 확인 → 발행 기록 성공
7. 성과 입력 → 후보 화면에 "지난 게시 1편 기록(참고만)" 표시
8. 승인 후 대본 수정 → 다시 "검수 대기", 예전 영상 ZIP 409

주의: 연결한 파일럿 C 영상은 첫 대사를 줄이기 **전** 버전으로 만든 것이라, 새 대본 v1의 첫 대사("이 단계, 하면 뭐가 달라질까요?")와 영상 속 첫 대사가 조금 다르다. 흐름 점검용이며, 실제 사용에서는 "검수용 영상 만들기"로 새로 만든다. 또한 파일럿 영상은 예전 방식이라 "검수 전 미리보기" 워터마크가 구워져 있다.
