# 스튜디오 2.0 — 구현 계획

- 근거: [AUDIT.md](AUDIT.md)(현재 상태), [DESIGN.md](DESIGN.md)(대안 비교·확정안)
- 작업 방식: 단계마다 작업 브랜치(`studio-2.0/<단계>`) → 실패하는 테스트 먼저(TDD) → 구현 → 검증 → 사용자 확인 후 `main` 반영
- 원칙: 기존 기능을 다시 만들지 않는다. `recipe-core / video / publishing / apps/studio` 구조와 검수·승인·버전 원칙을 그대로 쓴다.

## 단계 한눈에 보기

| 단계 | 내용 | 비용 | 사용자 승인 필요 | 예상 기간 |
| --- | --- | --- | --- | --- |
| 0 | 코드 감사 + 음성 캐시 결함 수정 | 0원 | — | **완료** |
| 1 | 작업 관리(진행·취소·재시도), 쉬운 오류, AI 결과 승인 차단 | 0원 | — | 2~3일 |
| 2 | 웹 안에서 AI 대본·장면 재생성 + 예산 한도 | 회당 수 원~수십 원 | **API 키·모델·월 한도** | 2~3일 |
| 3 | 블로그 2.0 + 영상·블로그·SNS 일관성 검사 + 게시 기록 | 0원 | — | 2일 |
| 4 | 로그인·보안 + 다른 PC에서 접속(터널) | 0원 | **외부 공개** | 2일 |
| 5 | 인스타그램 공식 게시(모의 → 실제) | 0원 | **Meta 앱, 어머니 계정, 실제 게시** | 3~4일 |
| 6 | 운영: 백업·복구, 자동 실행, 설치 안내 갱신 | 0원 | — | 1~2일 |

1·3단계는 승인 없이 바로 진행할 수 있다. 2·4·5단계는 표의 승인을 받은 뒤 실제 연결을 시작한다. 모의 테스트까지는 승인 전에도 만든다.

## 1단계 — 작업 관리와 안전장치

**목표**: 오래 걸리는 일(음성·렌더, 이후 AI·게시)을 화면에서 보고, 멈추고, 다시 시도할 수 있게 한다. 원본을 어긴 대본은 승인 자체를 막는다.

| # | 작업 | 위치 | 먼저 쓸 테스트 |
| --- | --- | --- | --- |
| 1.1 | `jobs` 표 추가(종류, 상태, 진행률, 단계, 사용자용 오류, 상세, 시도 횟수, 예상·실제 비용). 기존 `renders`는 그대로 두고 job과 연결 | `db.ts`, `repo.ts` | 생성·상태 전이·재시작 시 진행 중 작업을 "중단됨"으로 표시 |
| 1.2 | 렌더 취소: Remotion `makeCancelSignal`, 음성 단계는 `AbortSignal` | `pipeline.ts`, `video/render.ts` | 취소 요청 → 상태 "취소됨", 임시 파일 정리 |
| 1.3 | 재시도: 실패·취소된 작업을 같은 입력으로 새로 실행. 승인 상태를 다시 확인 | `app.ts` | 승인 풀린 뒤 재시도 → 409 |
| 1.4 | 오류 문장 변환표: 내부 오류 → "음성 프로그램이 꺼져 있어요. VoiceStudio를 켜고 다시 시도해 주세요" 등 | `server/errors.ts` (신규) | 대표 오류 8종 변환 |
| 1.5 | **원본 위반 승인 차단**: `canApprove`에 `checkScript` 결과를 넘겨 `error` 등급이 하나라도 있으면 승인 API가 409 (지금은 체크리스트·검수자 이름만 봄). 출처(템플릿·AI·직접 작성)와 관계없이 적용 | `recipe-core/workflow.ts`, `app.ts` 승인 경로 | 원본에 없는 분량 → 승인 거부, 수정 후 승인 가능 |
| 1.6 | 화면: 진행 막대 + 단계 + 취소 버튼, 실패 시 안내 + "다시 시도" | `VideoStep.tsx`, 공통 `JobStatus` | Playwright: 취소·재시도 흐름 |

**완료 기준**: 테스트 통과 + 브라우저에서 렌더 시작 → 취소 → 재시도 → 완료를 직접 확인.

## 2단계 — 웹 안에서 AI 생성 (승인 후 실제 연결)

| # | 작업 | 위치 | 먼저 쓸 테스트 |
| --- | --- | --- | --- |
| 2.1 | 생성기 인터페이스 `ScriptGenerator` + 기존 템플릿·붙여넣기를 그 아래로 정리 | `recipe-core/generator/` | 기존 테스트 그대로 통과 |
| 2.2 | 장면 하나 다시 쓰기용 프롬프트·응답 검증(순수 함수) | `recipe-core/generator/prompt.ts` | 다른 장면·재료 카드 불변 |
| 2.3 | Claude 연결: 공식 SDK, structured outputs(JSON 스키마), 사용량 기록, 시간 초과·취소 | `server/ai/claude.ts` | **모의 응답**(SDK 클라이언트 주입)으로 성공·형식 오류·429·취소 |
| 2.4 | 예산: 월 한도, 요청 전 예상 비용, 초과 시 시작 거부, 월별 사용 합계 | `server/budget.ts` | 한도 경계값 |
| 2.5 | 설정 화면: 연결 상태(키 값은 절대 표시 안 함), 모델 선택과 회당 예상 비용, 월 한도 | `CharacterPage` 옆 "설정" | 키가 응답·로그에 없음 |
| 2.6 | 대본 화면: "AI로 대본 만들기", 장면별 "이 장면 다시 쓰기", 결과는 새 버전(승인 해제) | `ScriptStep.tsx` | Playwright(모의 AI) |
| 2.7 | **실제 통합 테스트**(승인 후): 호두정과로 1회 생성 → 원본 위반 0, 비용 기록 확인 | 수동 + 기록 | — |

AI 결과는 항상 `enforceSourceData` → `checkScript` → (오류 시 승인 차단)을 거친다. 키가 없으면 템플릿·붙여넣기로 계속 쓸 수 있다.

## 6단계 — 운영

- 설치 안내서(`docs/LOCAL_SETUP` 계열) 갱신, 장애 시 확인 순서표
