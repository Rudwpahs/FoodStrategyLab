- 근거: [blog-research.md](blog-research.md) (네이버 공식 가이드 5종 + 실제 게시물 21건 분석), [sources.md](sources.md) F11·F12

## 1. 원칙: AI가 대신 쓰는 블로그가 아니라, 연구자의 지식을 편집하는 블로그

| 근거 | 내용 |
| --- | --- |
| [공식] 네이버 「AI 시대에 사용자의 선택을 받는 콘텐츠 작성 가이드」(2026-05-26) | 5원칙 중 첫째가 **직접 경험한 지식**. AI 도구 사용 자체는 불이익이 아니지만, 기계적으로 생성·요약한 글은 AI 브리핑 인용에서 걸러질 가능성이 높다고 밝힘 |
| [공식] 같은 가이드 실전편(2026-06-04) | 실패와 해결, 대안 비교, 이미지 속 정보의 텍스트 병기 |
| [공식] 웹 콘텐츠 스팸 사례(2026-07-06) | 키워드 반복·남용, AI 대량 생산 |
| [관찰] 표본 21건 | 실패와 원인까지 쓴 글은 1건. 효능 주장은 출처 없이 나열(4건). "실패 없는·황금레시피"류 보증 문구에 근거 없음 |

→ **이희재 블로그의 차별점은 실제 실패·판단 신호·이유.** 반대로 경험을 지어내면 가장 크게 잃는다.

## 2. 스튜디오가 하는 일과 하지 않는 일

| 한다 | 하지 않는다 |
| --- | --- |
| 원본 레시피의 재료·분량·순서를 그대로 옮긴다 | 경험·추억·실패담을 상상해서 쓴다 |
| 연구자 답변을 **문장 그대로** 해당 소제목 아래 넣는다 | 답변을 "더 자연스럽게" 바꿔 쓴다 (다듬기는 사람이 화면에서 직접) |
| 답이 없는 필수 질문은 "[연구자 답변 대기]"로 남긴다 | 빈 칸을 그럴듯한 문장으로 메운다 |
| 승인·답변·본인 확인이 모두 있어야 "게시 준비 완료" | 승인 전 "검토한" 표현을 쓴다 |
| 원본·답변에 없는 분량, 1인칭 경험 문장, 상투구, 효능 표현을 점검한다 | 검색 상위 노출을 약속하는 SEO 공식(글자 수·사진 수·키워드 횟수)을 적용한다 |

## 3. 글 유형 4가지

| 유형 | 누구의 어떤 궁금증 | 소제목 순서 (코드 `SECTION_ORDER`) | 필수 질문 |
| --- | --- | --- | --- |
| 생활 요리 이야기형 | 집에서 처음 만들려는 사람 | 만드는 이유 → (기억) → 재료 → 만드는 법 → (핵심 단계·실패·해결·수업 질문) → 한 줄 팁 → (보관·주의) | 이 음식을 언제, 왜 만들게 되셨어요? |
| 전문가 조리 노트형 | 실패해 봤거나 더 잘 만들고 싶은 사람 | 가장 중요한 한 단계 → 조리 노트(원리) → 자주 보는 실패 → 실패를 줄이는 방법 → (방법을 고른 이유) → 재료 → 만드는 법 → (수업 질문) → 한 줄 팁 → (주의) | 핵심 단계, 실패, 해결법 |
| 음식문화·전통조리 해설형 | 음식의 배경이 궁금한 사람 | 음식에 담긴 이야기 → (만드는 이유·기억) → 조리 노트 → 재료 → 만드는 법 → (핵심 단계·보관·주의·참고 자료) | 유래·전통적 쓰임 (출처와 함께) |
| 조리 실험·비교 분석형 | 이유를 알고 싶은 사람 | 직접 비교해 본 결과 → 핵심 단계 → 조리 노트 → (고른 이유·실패·해결) → 재료 → 만드는 법 → (주의·참고 자료) | 직접 비교한 결과, 핵심 단계 |

괄호는 선택 질문 — 답이 있을 때만 소제목이 생긴다. 실험·비교형은 **실제로 비교해 본 적이 없으면 쓸 수 없다**(필수 질문이 비면 게시 불가).

## 4. 질문지

스튜디오 [게시] 화면에서 글 유형을 고르면 질문이 나온다 (공통 12문항, 코드 `EXPERT_QUESTIONS`). 호두정과처럼 구체적인 인터뷰가 필요하면 [blog-research.md 8장](blog-research.md)의 17문항(배합 이유, 시럽 판단 신호, 젓는 시점, 튀김 vs 오븐, 실패 원인, 정과·강정·빠스 구분 등)을 대화 대본으로 쓰고, 답을 해당 칸에 옮긴다.

- 질문 하나에 사실 하나. 해 보지 않은 것은 비워 둔다.
- 가족이 대신 입력했다면 연구자가 읽고 **"본인 확인"**을 체크해야 한다. 답을 고치면 확인이 풀린다.
- 음성 답변(받아쓰기)은 다음 단계 — VoiceStudio 받아쓰기 모델 설치 후 연결 예정.

## 5. 문체 점검 (자동, `lintBlog`)

| 점검 | 수준 | 근거 |
| --- | --- | --- |
| 연구자 답변에 없는 1인칭 경험 문장("제가", "저는", "직접 해 보니") | **오류** | 지어낸 경험 = 최고 위험 (blog-research 6장 #15) |
| 상투구: 알아보겠습니다 / 중요합니다 / 황금레시피 / 실패 없는 / 누구나 / 일품 / 자꾸 손이 가는 / 도움이 되셨길 / 소개해 드릴게요 / 누가 만들어도 | 경고 | 표본 관찰 + 공식 가이드 |
| 요리 이름 7회 이상 | 경고 | 공식 스팸 사례(키워드 반복). 6회는 **내부 기준**이지 네이버 기준이 아니다 |
| 효능 단어(면역·혈당·살균·다이어트 등) | 경고: 출처 필요 | 공식 가이드 "부정확한 정보" |
| 느낌표·물결 과다 | 경고 | 전문가 톤 |

## 6. 영상과 맞추기 (`checkConsistency`)

게시 화면에서 자동으로 대조한다: 영상 대본의 원본 위반, 블로그에 빠진 재료·순서, 원본·답변에 없는 분량, 영상 팁이 블로그에 없음, 승인 전 "검토" 표현. 오류가 있으면 화면에 빨간 줄로 표시된다.

## 7. 발행 전 점검표

- [ ] 대본 승인 완료 (승인 뒤 수정 없음)
- [ ] 필수 질문 답변 + 연구자 본인 확인
- [ ] 문체 점검 오류 0
- [ ] 일관성 검사 오류 0
- [ ] 사진 속 정보(온도, 시럽 상태)는 본문 글로도 적었다
- [ ] 효능·전통 유래 주장에 출처가 있다
- [ ] 협찬·클래스 홍보가 있으면 첫 줄에 밝혔다
