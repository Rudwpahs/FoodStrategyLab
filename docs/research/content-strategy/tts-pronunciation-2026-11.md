# 목소리 발음 고치기: 숫자 읽기·겹받침·이름 (2026-11-19)

사용자 지적: "떫 발음을 못해 … 한컵이 아니라 일컵이라 하고", 그리고 "이희재의"가 받아쓰기에서 "이제"로 나옴.
이 문서는 고치기 전에 한 조사(웹·소스 코드·실제 영상 받아쓰기·목소리 엔진 직접 실험)와, 거기서 고른 방법과 이유를 적는다.
구현: `packages/recipe-core/src/speakable.ts` (목소리에만 쓰고 자막·대본은 그대로).

표기: **[확인]** = 원문·소스·실험으로 직접 확인, **[2차]** = 검색 요약·보도 등 2차 자료(원문 못 봄), **[추정]** = 근거가 약하거나 없음.

## 1. 우리 목소리 엔진은 한국어를 어떻게 읽나

| 사실 | 근거 |
| --- | --- |
| VoxCPM2는 "토크나이저 없는" 확산·자기회귀 TTS로, 글자를 언어 모델 토큰으로 받아 바로 소리를 만든다. 한국어 발음 변환기(G2P)가 없다. 지원 30개 언어에 한국어 포함 | [확인] OpenBMB/VoxCPM README (저장소 2026-11-09 커밋) https://github.com/OpenBMB/VoxCPM |
| VoxCPM의 `normalize=True` 글자 정리는 중국어·영어(wetext)만 한다. 한국어 문장은 "영어"로 분류돼 영어 규칙을 탄다 → 쓰면 안 됨 | [확인] `src/voxcpm/utils/text_normalize.py` `TextNormalizer.normalize` (lang = zh if 한자 else en) |
| 숫자 발음이 약한 이유: 학습 데이터에 숫자를 글자로 바꾸는 처리(ITN)를 하지 않았다. 제작진 권고: **"모델에 넣기 전에 글자 정규화를 하라"** | [확인] VoxCPM 이슈 #164 (2026-01-24 협업자 liuxin99 답변) https://github.com/OpenBMB/VoxCPM/issues/164 |
| 발음 기호 입력(`{pinyin}`)은 중국어 병음만 언급되고, 그마저 불안정하다는 보고 | [확인] VoxCPM 이슈 #172 https://github.com/OpenBMB/VoxCPM/issues/172 |
| 엔진을 감싼 VoiceStudio(배포 커밋 429f1e5)는 보내기 전에 `normalize_for_tts`를 돈다. 한국어 숫자는 **그대로 둔다**(num2words가 한국어를 안전하게 못 다룸). 단 "20~30"처럼 물결표 범위만 "20에서 30"으로 바꾼다 (OmniVoice가 "20~30"을 "23"으로 읽은 사고 때문) | [확인] `backend/services/text_normalization.py` (`_RANGE_JOINERS`, `_num2words_lang`) |
| VoiceStudio에는 단어 바꿔 읽기 사전(`pronunciation.py`)이 있지만 우리가 쓰는 `/v1/audio/speech` 경로에서는 정규화만 한다 | [확인] `backend/api/routers/openai_compat.py` 726행 부근 |

→ 결론: 지금 "1컵"은 숫자 그대로 엔진에 들어가고, 엔진이 스스로 한자어 "일"로 읽는다. "떫" 같은 드문 글자는 엔진이 배운 예가 적다. 우리 쪽에서 글자를 고쳐 넘기는 수밖에 없다.

## 2. 실제 영상에서 확인한 잘못 읽기 (2026-11-19 견본 4편 받아쓰기)

로컬 faster-whisper small로 `batch7` 견본 4편을 받아썼다. 받아쓰기 자체도 틀리므로(작은 모델) "엔진이 틀렸다"와 "받아쓰기가 틀렸다"를 다 구별할 수는 없다. 대사와 다르게 나온 곳:

| 대사 | 받아쓰기 | 판단 |
| --- | --- | --- |
| 한 입 먹자마자 **떫어요**! | 떴어요 | 'ㄼ' 잘못 읽음 (사용자 지적과 같음) |
| 찬물에 헹구면 **떫은맛이** 줄어든대요 | 떳은 맛이 | 'ㄼ' 잘못 읽음 |
| **떫은맛** 범인 검거 완료! | 같은 맛 범인검거 | 'ㄼ' 잘못 읽음 |
| 설탕 **1컵**, 물엿 **1/2컵**까지요 | 설탕 1컵, 물렷 **1분 1컵**까지요 | 분수를 엉뚱하게 읽음 ("일분 일컵"류). 1컵은 받아쓰기가 숫자로 적어 일/한을 구별 못 함 |
| **이희재의** 맛 연구소 (보낸 글자: 이히재에) | 이제 맛연구소 / 이재재의 맛연구소 / 이재재 마듬구소 | 이름이 뭉개짐 (3편) |
| **희재** 선생님 (보낸 글자: 히재) | 피제 / 희재 | 1편에서 뭉개짐 |
| 굵은소금, 끓는 물, 넉넉한, 두세 번 | 그대로 | 흔한 겹받침·연음은 잘 읽음 |
| 140도 정도, 30초, 4분, 400g, 100g | 그대로(숫자로 적힘) | 받아쓰기가 숫자로 적어 읽은 방식은 알 수 없음 |

## 3. 숫자 읽기 규칙 (고유어 수 / 한자어 수)

| 규칙 | 근거 |
| --- | --- |
| 단위(세는 말) 앞에서 수는 관형사 꼴로 바뀐다: 한·두·세·네·스무 (한 개, 스무 개) | [2차] 한국경제 '맞춤법 바로 알기' (고유어 수사가 관형어로 쓰일 때 '한, 두, 세'로 바뀜) https://sgsg.hankyung.com/article/2019060748081 · [확인] g2pK `numerals.py` (한 두 세 네…, 20 → 스무) |
| 단위가 한자어면 한자어 수, 고유어면 고유어 수가 기본이지만 자주 쓰는 단위는 예외가 많고, 어문 규범에 정해진 목록은 없다 | [2차] 온라인가나다 답변을 옮긴 자료(원문 미확인) https://www.yugacrew.com/yugawiki/%ED%95%9C%EC%9E%90%EC%96%B4%20%EC%88%98 · 한교닷컴 칼럼 https://www.hangyo.com/news/article.html?no=76573 |
| 고유어 수는 99까지. 사람·물건·시간(시각 1~12시)·나이는 고유어, 분·초는 한자어 | [2차] Wikipedia "Korean numerals" https://en.wikipedia.org/wiki/Korean_numerals · [확인] NeMo 한국어 시각 시험 자료 ("오후 3시 반 → 오후 세시 반", "10시30분 → 열시 삼십분") |
| 단위를 나타내는 명사는 띄어 쓴다 (한 개, 차 한 대). 수는 만 단위로 띄운다 | 한글 맞춤법 제43·44항 [추정: 조항 번호는 기억, 이번에 원문 다시 못 봄] |
| 넷이나 다섯: 네댓·너덧·너더댓·네다섯 모두 허용 | [2차] 한국경제 칼럼(위와 같음) |
| 육은 모음 뒤에서 [륙] (오륙 분), 6월·10월은 유월·시월 | [추정: 일반 지식, 이번에 원문 확인 못 함] |

**공개 도구는 요리 단위를 모른다 [확인]:**
- g2pK(Apache-2.0)의 고유어 단위 목록(`BOUND_NOUNS`)에 컵·큰술·작은술이 없다 → "1컵"을 "일컵"으로 만든다. https://github.com/Kyubyong/g2pK (2020-08 마지막 커밋)
- NVIDIA NeMo 한국어 정규화(Apache-2.0)의 고유어 단위 목록(`counter_suffix.tsv`)은 개·명·병·마리·송이·포기·사람·자루·채·켤레·그루·벌·잔·장·권·살뿐이고, 고유어는 39까지만 다룬다. 시간 단위 `h`는 한자어("백이십삼 시간"). https://github.com/NVIDIA/NeMo-text-processing (2026-09-18 커밋, `nemo_text_processing/text_normalization/ko`)
- 둘 다 파이썬이라(NeMo는 pynini 필요) Node 서버에 그대로 넣기도 어렵다.

→ 요리 단위(컵·큰술·작은술·T·t·C·g·ml·도·분·초·인분 등)를 우리 표로 직접 둔다. NeMo의 단위 이름(g → 그램, ml → 밀리리터, ° → 도, % → 퍼센트)과 분수 읽기("1/2 → 이분의 일", "1과1/2 → 일과 이분의 일")는 그대로 따랐다.

**계량 관습:** 레시피의 1/2컵은 말로 "반 컵", 1.5큰술은 "한 큰술 반"이 자연스럽다 [추정: 관습. 국어 규범이 아니라 말하는 방식]. 3~4분은 "삼사 분", 2~3컵은 "두세 컵" (이웃한 수 어림수) [추정: 일반 지식. '네다섯' 허용은 위 2차 자료].

## 4. 겹받침과 소리 나는 대로 적기 (표준 발음법)

g2pK에 실린 표준 발음법 조항 사본(`g2pk/rules.txt`)과 검색 요약으로 확인 [확인/2차]:
- 제10항: 겹받침 'ㄳ, ㄵ, ㄼ·ㄽ·ㄾ, ㅄ'은 어말·자음 앞에서 [ㄱ, ㄴ, ㄹ, ㅂ]. 넓다[널따], 여덟[여덜]. 다만 '밟-'은 자음 앞에서 [밥], '넓죽하다·넓둥글다'는 [넙].
- 제14항: 겹받침 뒤에 모음으로 시작하는 조사·어미가 오면 뒤엣것만 넘겨 읽는다 → 떫은[떨븐].
- 제25항: 어간 받침 'ㄼ, ㄾ' 뒤 어미의 'ㄱ, ㄷ, ㅅ, ㅈ'은 된소리: 넓게[널께], 떫지[떨찌].
- 제12항 붙임 1: 'ㅂ(ㄼ)' + 'ㅎ' → [ㅍ]: 밟히다[발피다], 넓히다[널피다].
- 제18항: 'ㅂ(ㄼ)'은 'ㄴ, ㅁ' 앞에서 [ㅁ]: 밟는[밤는]. 제20항: 'ㄹ' 뒤 'ㄴ'은 [ㄹ].
- 제5항 다만 3·4: 자음 뒤 'ㅢ'는 [ㅣ](희망[히망]), 조사 '의'는 [에]도 허용.
- 원문: 국립국어원 「표준어 규정」 제2부 표준 발음법 https://www.korean.go.kr/front/page/pageView.do?page_id=P000101&mn_id=95 (이 세션에서는 국립국어원 누리집 접속이 막혀 g2pK 사본과 검색 요약으로 대조)

## 5. 문장 전체를 소리 나는 대로 바꾸면 좋아질까? — 근거가 갈린다

| 근거 | 내용 | 방향 |
| --- | --- | --- |
| VoxCPM 제작진 (이슈 #164) | 숫자는 넣기 전에 글자로 풀라 | 숫자 풀기 **찬성** [확인] |
| EmergentTTS-Eval (NeurIPS 2025, arXiv 2505.23009) | 단순 규칙 정규화는 오히려 점수를 떨어뜨릴 때가 있고(예: 금액을 이상하게 풀어 씀), 문맥을 아는 정규화는 "어려운 발음" 점수를 크게 올렸다 | 정규화는 **맞게만 하면** 찬성 [2차: 검색 요약] |
| KVoiceBench (2026, arXiv 2605.27984) | 한국어 TTS 전에 숫자·기호·영문 섞인 말을 11가지 규칙으로 읽는 말로 바꾼다 | 숫자 풀기 **찬성** [2차] |
| Perquin 외 (2020, arXiv 2010.10694) | 잘 정리된 데이터로 배운 모델은 글자 입력으로도 발음 오류가 늘지 않는다. 영어에서는 글자 vs 발음 입력 결과가 엇갈린다 | 전부 바꾸기 **불필요** [2차] |
| Fish Speech 이슈 #1263 (2026-04) | 모든 글자에 발음 표시를 달면 발음은 고쳐지지만 "말이 매우 부자연스러워졌다", 일부만 달면 그 부분만 어색 | 전부 바꾸기 **위험** [확인] |
| Azure·Polly 같은 상용 TTS | 발음 사전·`sub alias`로 문제 단어만 바꿔 읽게 한다 | **골라 바꾸기** [2차] https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-synthesis-markup-pronunciation |
| 타입캐스트 공식 가이드 | 날짜·기호는 실제로 읽을 말로 풀어 쓰고 들어 보며 확인 | 숫자·기호 풀기 **찬성** [2차] https://typecast.ai/kr/learn/?p=7492 |
| 실제 견본 (2장) | 굵은소금·끓는·넉넉한 같은 흔한 겹받침·연음은 이미 잘 읽고, 떫(드문 글자)만 틀림 | **골라 바꾸기** [확인] |
| g2pK·MeloTTS·GPT-SoVITS | 발음 변환을 쓰는 모델은 **학습 때도** 같은 변환을 거친 글자로 배웠다. VoxCPM2는 맞춤법 글자로 배웠다 | 학습과 다른 입력은 위험 [확인: 소스] |

한국어로 "소리 나는 대로 쓴 글"을 맞춤법 글자로 배운 신경망 TTS에 넣었을 때의 비교 연구는 찾지 못했다 (공백).

## 6. 고른 방법

| 안 | 내용 | 판단 |
| --- | --- | --- |
| (a) 문장 전체 발음 변환 (g2pK식: 연음·경음화·비음화 전부) | 사용자가 처음 말한 "연음법칙 적용한 대본" | **채택 안 함.** 형태소 분석기(mecab)가 필요하고 Node에 없다. 엔진이 이미 잘 읽는 말("맛있어요"→"마시써요")까지 학습 때 못 본 글자로 바뀐다. 전부 바꾸면 부자연스러워졌다는 보고(Fish Speech). 실제 견본에서 흔한 말은 문제가 없었다 |
| **(b) 골라 바꾸기** | 숫자+단위, 겹받침 'ㄼ', 이름 | **채택.** 실제로 틀린 곳(숫자·분수·떫·이름)만 고치고, 바꾸는 규칙은 표준 발음법·숫자 읽기 규칙에서 온다 |
| (c) 대본 작성 단계에서 숫자를 글자로 쓰게 하기 | AI 대본에 "한 컵"으로 쓰게 | 채택 안 함: 원본 분량 표기(원칙 1)와 자막이 숫자를 보여야 하고, 다른 작업자가 대본 프롬프트를 맡고 있다 |
| (d) 엔진 쪽 발음 표시·미세조정 | 한국어 발음 표시 기능 없음, 미세조정은 비용·시간 | 채택 안 함 |

**(b)의 범위:**
1. 숫자: 단위가 고유어로 세는 말이면 한·두·세(한 컵, 두 큰술, 네 통), 한자어로 읽는 말이면 일·이·삼(오 분, 백사십 도, 일 인분, 오백 그램). T/t/C는 큰술/작은술/컵. 1/2+단위는 "반", 1.5+고유어 단위는 "한 컵 반", 3~4분은 "삼사 분", 2~3컵은 "두세 컵". 날짜·전화번호·시각처럼 단위 없는 숫자 묶음은 그대로 둔다(VoiceStudio도 같은 원칙: 모호하면 손대지 않음). 읽는 말이 바뀌면 붙은 조사도 맞춘다(4T는 → 네 큰술은).
2. 겹받침 'ㄼ'만: 제10·12·14·18·20·25항대로 (떫은맛→떨븐맛, 떫죠→떨쬬, 떫어요→떨버요, 여덟→여덜). 엔진이 이미 맞게 읽는 얇게·넓은·짧게는 빼고(7장 실험), 다른 겹받침(ㄺ·ㅀ·ㄻ·ㅄ·ㄶ)은 견본에서 잘 읽어서 바꾸지 않는다.
3. 이름: 아래 7장 실험으로 정한다.

**띄어쓰기:** 읽는 말은 맞춤법대로 띄운다("한 컵", "오백 그램"). 엔진이 배운 글과 같은 꼴이기 때문이다. 자막 어절 수와 달라져도 되도록 받아쓴 어절 시간을 자막 어절에 글자 단위로 맞추는 함수(`alignWordTimes`)를 넣었다 (예전에는 받아쓴 어절 수가 자막과 정확히 같을 때만 시간을 썼는데, 받아쓰기가 "맛연구소"처럼 붙여 적는 일도 흔해서 자주 버려졌다).

**자동 검사(받아쓰기 대조):** 대사와 받아쓴 말을 둘 다 같은 규칙으로 읽는 말로 바꾼 뒤 비교한다. 받아쓰기가 "한 컵"이나 "1컵", "떫은맛"이나 "떨븐 맛" 어느 쪽으로 적어도 맞게 읽은 것으로 본다.

## 7. 목소리 엔진 직접 실험 (VoxCPM2, 로컬 CPU)

방법: 이 컴퓨터에 내려받아 둔 VoxCPM2(openbmb/VoxCPM2, voxcpm 2.0.3)를 CPU로 돌려, 배포와 같은 방식(맛조수 기준 녹음 `tools/setup/matjosu-reference.wav` + 기준 문장 이어 말하기, cfg 2.0, 10단계, 같은 시드)으로 같은 문장의 원문(A)과 바꾼 글자(B, C)를 읽혔다. 결과를 faster-whisper small로 받아썼다. 받아쓰기는 소리를 맞춤법대로 "고쳐" 적는 경향이 있고 작은 모델이라 틀리기도 해서, 받아쓰기만으로 발음을 판정하는 것은 한계가 있다 (사람이 들어 보는 확인이 남아 있음). 받아쓰기가 "한 컵"과 "일 컵"을 둘 다 "1컵"으로 적는 문제를 피하려고, 숫자·기호 토큰을 막은 받아쓰기(숫자 금지)도 함께 돌렸다. 실험 스크립트는 세션 임시 폴더에만 있고 저장소에는 넣지 않았다. 참고: 이 실험은 VoiceStudio를 거치지 않아, 배포에서 VoiceStudio가 하는 "3~4 → 3에서 4" 변환은 빠져 있다.

**결론**
- 숫자+단위: 원문 그대로면 엔진이 "일컵·일큰술·일단·사통"으로 읽고 분수를 뭉갠다. 읽는 말로 풀면 모두 고쳐졌다 → 채택 근거 확정.
- 'ㄼ': 떫(드문 글자)은 원문이면 [떠/떡]으로, 바꾼 글자면 [떨]로 들렸다 → 채택. 얇게·넓은·짧게는 원래 맞아서 규칙에서 뺐다(`READS_FINE`).
- 띄어쓰기: 차이 없음 → 맞춤법대로 띄운다.
- 이름: 세 가지 글자 모두 받아쓰기에서 "이제"로 나왔다. 엔진이 '히'를 약하게 읽는 것인지(모음 사이 ㅎ 약화), 받아쓰기(작은 모델)가 못 알아듣는 것인지 받아쓰기만으로는 가릴 수 없다. **근거가 갈려서 지금 방식(표준 발음 [이히재에])을 그대로 두고 아래 선택지를 제안한다.**

**이름 선택지 (사람이 들어 보고 고를 것)**
1. 그대로 둔다 (표준 발음 [이히재에]). 엔진은 맞게 읽는데 받아쓰기만 틀릴 수 있다.
2. 성과 이름 사이를 살짝 끊는다 ("이, 희재의" 또는 "이 희재의"). 모음 사이 'ㅎ'은 약해지기 쉬운데([2차] ㅎ 약화 설명 https://elon.io/grammar/korean/pronunciation/h-weakening-deletion), 끊으면 '희'의 ㅎ이 또렷해질 수 있다 [추정]. 부자연스럽게 들릴 위험.
3. 기준 녹음 문장을 이름이 또렷한 녹음으로 바꾼다 (목소리 정체가 바뀌므로 원칙 5의 고정 녹음을 다시 정해야 함).
4. 받아쓰기 쪽: 자동 검사가 이름을 계속 "다르게 들림"으로 알리면 사람이 들어 보고 넘긴다 (지금 동작).

## 8. 남은 일·한계

- 사람이 직접 들어 보는 확인: 클라우드 GPU에서 만든 실제 음성으로 떫은맛·분수·이름을 들어 볼 것.
- 숫자 단위 표는 요리 대본에 나오는 말 위주다. 새 단위가 나오면 `speakable.ts`의 표에 더한다 (모르는 단위는 엔진처럼 한자어로 읽는다).
- "2분"(두 분, 사람)처럼 단위가 겹치는 말은 요리 대본에서 흔한 쪽(시간)으로 읽는다.
- 이 변경으로 숫자·'ㄼ'·이름이 든 대사는 음성 파일 이름(읽는 말 기준)이 바뀌어 다음 제작 때 다시 만들어진다.
- 이 세션에서는 국립국어원·arXiv·KoreaScience 누리집에 직접 접속이 막혀, 그 자료는 검색 요약(2차)과 g2pK에 실린 조항 사본으로만 대조했다. GitHub 원문(VoxCPM·VoiceStudio·g2pK·NeMo 소스와 이슈)은 직접 읽었다.
- 소리 실험은 CPU·작은 받아쓰기 모델·문장 한 번씩(같은 시드)이라 표본이 작다. 숫자 결과는 차이가 뚜렷했고, 'ㄼ'은 방향이 일관됐다.
