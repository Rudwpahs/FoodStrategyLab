## 1. 시간 흐름 점검 (코드)

음성 한 줄이 화면에 나오기까지:

1. VoiceStudio(`/v1/audio/speech`) → MP3. VoiceStudio가 앞뒤 무음을 자르고 최고 음량을 -2dBFS로 맞춘다(`_run_tts`).
2. 말 빠르기를 '보통'이 아닌 것으로 고르면 ffmpeg `atempo`로 늘이거나 줄인다(`changeTempo`). 기본값(보통)은 손대지 않는다.
3. `speechBounds`(10ms 칸, -42dB)로 말 시작·끝 → 앞 무음은 `trimBefore`로 건너뛰고, 장면 길이 = 말소리 + 0.45초.
4. 받아쓰기(VoiceStudio `/v1/audio/transcriptions`, 클라우드는 WhisperX = faster-whisper large-v3 + wav2vec2 정렬)로 단어 시간 → 자막 묶음(1~3어절, 13자).
5. Remotion 렌더(AAC) → 음량 맞추기(loudnorm) → 촬영 소리(amix) → 배경 음악(amix). 화면은 다시 인코딩하지 않는다.

점검 결과:

| 항목 | 결과 |
| --- | --- |
| 프레임 반올림 | 앞 무음 자르기는 프레임 단위(반올림)인데 단어 시간은 반올림 전 값으로 옮겨, 최대 반 프레임(17ms) 어긋날 수 있었다 → 고침 (같은 반올림 값 기준) |
| 단어 수 비교 | `measuredWords`가 "받아쓴 단어 수 = 대본 어절 수"일 때만 시간을 썼다 → 1·2장의 큰 원인 |
| 숫자 낱말 | WhisperX 정렬기는 숫자·기호가 든 낱말("400g", "1/2컵")에 시간을 주지 못하고, VoiceStudio는 그런 낱말을 빼고 돌려준다(`_openai_words`) → 숫자가 든 대사는 늘 단어 수가 달라졌다 |
| 입 모양 | `mouthOpen(frame)` = 일정한 사인파 두 개. 소리와 무관 |
| MP3 앞 여백 | LAME 헤더의 앞 여백은 ffmpeg가 모든 단계에서 똑같이 처리 → 상대 어긋남 없음 |
| AAC 앞 여백 | AAC는 앞에 1024샘플(21.3ms)을 두고 MP4 편집 목록으로 가린다. 편집 목록을 무시하는 플레이어에서는 소리가 21ms 늦지만, 단계를 거듭해도 쌓이지 않는다(4장). 사람이 알아채는 한계(소리가 늦을 때 약 125ms, ITU-R BT.1359)보다 훨씬 작다 |

같은 묶음의 끝 장면 받아쓰기 "이제 맏연구소 수사 파일에…"(대본 "이희재의 맛 연구소 수사 파일에…")처럼, **모든 영상의 끝 장면은 "맛연구소"를 붙여 써서 단어 수가 달랐다.**

### 2-2. 깨끗한 음성 6줄 (VoxCPM2 맛조수, 예전 견본 `vcompare`)

- 받아쓴 단어 수 ≠ 대본 어절 수: **6줄 중 4줄** (small 모델 기준. "천국장 덮밥", "준비 물은", "조리노트", "맛연구소였어요")
- 쉼 뒤 첫 어절의 시작 오차 (기준: 소리 크기로 찾은 쉼 끝, 5곳):

| 방법 | 평균 오차 | 최대 |
| --- | --- | --- |
| 예전 (글자 수 비율) | 0.215초 | 0.513초 |
| 받아쓰기 시간 그대로 (글자 맞춤만) | 0.230초 | 0.390초 |
| **글자 맞춤 + 쉼에 맞추기 (새 방식)** | **0.002초** | 0.010초 |
| **받아쓰기 없을 때 새 어림 (쉼과 문장 끝 짝짓기)** | **0.002초** | 0.010초 |

같은 방법을 6장 실험 음성 12개(이어 말하기·조절 복제·지시문 없는 복제 × 4줄)에도 돌렸다: 쉼 경계 6곳에서 예전 평균 0.426초(최대 0.840초, 말줄임표 뒤) → 새 방식 0.003초(최대 0.010초). 두 묶음을 합치면 11곳, 예전 평균 0.33초·최대 0.84초.

받아쓰기(Whisper) 단어 시간은 쉼을 다음 낱말 앞에 붙이는 일이 잦아(위 둘째 줄: 쉼 뒤 낱말이 0.2~0.4초 이르게 잡힘) 그대로 쓰면 오히려 이를 수 있다. 그래서 소리 크기로 찾은 쉼에 시작을 맞춘다 — Whisper 시간을 무음 구간으로 바로잡는 stable-ts의 방법과 같은 생각이다.
주의: 기준(쉼 끝)도 소리 크기로 찾았으므로 쉼 경계에서는 맞을 수밖에 없다. 쉼이 없는 말 중간의 어절 시간은 이 방법으로 재지 못했다(정답 정렬 자료가 없음). 클라우드의 WhisperX는 wav2vec2 강제 정렬을 쓰므로 small 모델보다 낫다(WhisperX 논문·VoiceStudio 주석: Whisper 단독 ±100~300ms, 정렬 후 ±10~30ms).

## 3. 입 모양

- 견본 6줄에서 말하는 구간 중 쉼(-42dB 아래)의 비율: 3%·17%·19%·19%·24%·32% (평균 19%). 예전에는 이 동안에도 입이 계속 움직였다.
- 만화 캐릭터 입 맞추기의 표준적인 단순 방법은 소리 크기(RMS)를 0~1로 바꿔 입 벌림에 쓰고, 닫힐 때 부드럽게 하는 것이다(Live2D Cubism SDK 립싱크).
- 새 방식: 음성 파일을 프레임(1/30초)마다 RMS → -42dB(입 닫힘) ~ 그 파일의 상위 5% 크기(다 벌림)를 0~9로. 열 때는 바로, 닫힐 때는 프레임마다 0.55배로 줄인다. 2D 맛조수(실제 영상 위 작은 원)와 3D 맛조수가 함께 쓴다. 기록이 없으면(예전 렌더, 목소리 없음) 예전 파형.

## 5. 억양: 엔진이 어떻게 말투를 정하는가

### 5-1. 우리 요청이 실제로 어떻게 처리되는가 (VoiceStudio 고정 버전 429f1e5 코드)

- 목소리 프로필 = 기준 녹음 + 그 대본(`ref_text`). 요청에 `instruct`가 없으면 `generation_kwargs`가 **continuation(이어 말하기, '궁극 복제')** 을 고른다: `prompt_wav_path`·`prompt_text`·`reference_wav_path`에 같은 기준 녹음.
- VoxCPM2 README: 이어 말하기는 "기준 녹음에 이어서 말하며 음색·**리듬·감정·스타일**을 그대로 살린다". 반면 '조절 복제(controllable cloning)'는 기준 녹음에서 음색만 따고, 괄호 안 지시문으로 감정·빠르기·표현을 정한다.
- 대본을 비워 프로필을 만들면 VoiceStudio가 기준 녹음을 받아써서 대본을 채운다(`_auto_transcribe_reference`) → 여전히 이어 말하기. VoiceStudio API로 조절 복제를 쓰는 길은 **요청에 `instruct`(지시문)를 넣는 것뿐**이다.
- 기준 녹음(6개 모두): 5.4~8.9초, 끝 무음 0.03~0.05초, 마지막 말 "튀길까요?"(질문, 끝이 올라감; 맛조수는 끝 음높이 약 415Hz, 평균 약 350Hz).
  - VoxCPM 이슈 #272: 기준 녹음 끝에 무음이 없으면 기준 녹음 끝소리가 결과 앞머리에 새어 나온다는 보고, 끝에 0.5~1초 무음을 붙이면 나아졌다는 사용자 보고(2026-05, 2026-08). 그러나 VoiceStudio가 기준 녹음 앞뒤 무음을 0.05초만 남기고 자르므로(`_prepare_voxcpm_ref`) 우리 쪽에서 무음을 붙여도 소용이 없다.
- 그 밖의 설정: cfg 2.0, 단계 10 (VoiceStudio·VoxCPM 기본, 우리는 보내지 않음). `speed`(우리 기본 1.05)는 VoxCPM2가 **무시한다**(`generation_kwargs`에 없음) — 캐시 이름에만 들어간다. VoxCPM 자체 글자 정리(`normalize`)는 꺼져 있고 VoiceStudio의 `normalize_for_tts`가 대신 돈다.

### 5-2. 한국어 억양에서 중요한 점

- 해요체는 평서문과 의문문의 글자가 같고("먹었어요" / "먹었어요?") **끝 음높이로만** 갈린다. 글에서는 문장부호가 유일한 단서다(Jang 1998, CSTR; 한국어 학습 자료). K-ToBI: 평서 L%, 의문·감탄 등은 H%·LH%·HL% (Jun, K-ToBI 3.1).
- 그래서 평서문("이거예요.")이 끝에서 올라가면 듣는 사람에게는 질문처럼, 또는 어색한 '외국인 억양'처럼 들린다.
- 신경망 TTS 일반: 문장부호가 끊어 읽기·억양을 이끈다. 말줄임표는 쉼과 함께 머뭇거림을 더한다(ElevenLabs 가이드). 우리 대본 83줄은 모두 문장부호로 끝났고(없는 줄 0), 말줄임표 4번·물결 1번뿐이라 문장부호 정리로 얻을 것은 적다.

### 5-3. 실측: 지금 목소리(이어 말하기)의 문장 끝 음높이

`vcompare` 견본 6줄(클라우드와 같은 VoiceStudio 경로로 만든 맛조수), 쉼으로 나눈 덩어리의 끝 120ms 음높이 변화(반음, +는 올라감):

| 대사 | 덩어리 끝 | 변화 |
| --- | --- | --- |
| 잠깐! 청국장덮밥, 이렇게 하면 안 돼요! | "안 돼요!" | **+3.6** (질문처럼 올라감) |
| 원인은 이거예요. 이희재 연구자의… | "이거예요." | **+2.5** (질문처럼 올라감) |
| … 콩알 식감이 살아난다. | "살아난다." | -0.9 |
| 준비물은 이거예요! | | -2.0 |
| 바른 순서는 핵심 5단계, 전체 6단계는 블로그에! | "5단계," / "블로그에!" | -3.6 / -2.1 |
| 다음에 만들 때 꺼내 보게 저장! 이희재의 맛 연구소였어요. | "저장!" / "연구소였어요." | +0.7 / -1.9 |
| 이희재의 맛 연구소, 오늘의 실험! | "연구소," / "실험!" | +8.9 (쉼표 뒤 올림은 자연스러움) / -7.3 |

평서·감탄 문장 끝 9곳 중 2곳이 +2.4반음 넘게 올라갔다. 6장의 이어 말하기 평서문 4곳 중 1곳(+2.4)까지 합치면 13곳 중 3곳.

## 6. 실험: 이어 말하기 vs 조절 복제 (같은 대사·같은 시드)

로컬 CPU에서 VoxCPM2 2.0.3을 VoiceStudio와 같은 값(cfg 2.0, 단계 10, 다시 시도 끔, 맛조수 기준 녹음)으로 돌렸다. 시드 1, 대사 4줄 × 3방식 = 12개.

- **이어 말하기** (지금 방식): 기준 녹음 + 대본
- **조절 복제 + 지시문** (VoiceStudio에서 `instruct`를 보내면 되는 방식): "(cheerful bright young female voice, natural conversational Korean intonation, statements end with a gentle fall)대사"
- **지시문 없는 복제** (기준 녹음만. VoiceStudio API로는 고를 수 없는 방식, 비교용)

문장 끝 음높이 변화(반음, +는 올라감; 쉼으로 나눈 덩어리의 끝 120ms):

| 대사 | 자리 | 기대 | 이어 말하기 | 조절 복제 + 지시문 | 지시문 없는 복제 |
| --- | --- | --- | --- | --- | --- |
| 히재 선생님 노트에 범인이 있었어요. … | "있었어요." | 내림 | +0.5 | -1.4 | -0.6 |
| … 떫은맛이 줄어든대요. | "줄어든대요." | 내림 | +0.1 | **+4.8** | +1.9 |
| 재료는 그대로예요. 섞는 타이밍만 바꿔요. | "그대로예요." | 내림 | **+2.4** | +0.1 | **+9.9** |
| | "바꿔요." | 내림 | +1.3 | -3.2 | **+6.4** |
| 설탕은 듬뿍 넣었는데… 데치기를 건너뛴 게 문제일까요? | "문제일까요?" | 올림 | +4.9 | +0.8 (약함) | +10.3 |
| 방금 부친 김치전이 왜 벌써 축축해요? | "축축해요?" (왜-의문, 내림·올림 모두 가능) | — | +5.3 | +2.2 | -7.6 |
| 평균 음높이 (기준 녹음 약 350Hz) | | | 307~381Hz | 302~369Hz | 253~313Hz (목소리가 낮아짐) |

정리:
- 평서문 끝 4곳 중 2반음 넘게 올라간 곳: 이어 말하기 1곳, 조절 복제 1곳, 지시문 없는 복제 2곳(최대 +9.9).
- 조절 복제는 평서문 끝 평균이 가장 낮지만(+0.1 vs 이어 말하기 +1.0), "~일까요?" 같은 예/아니오 의문문의 올림이 약해져(+0.8) 질문이 평서문처럼 들릴 수 있다. VoxCPM 문서도 조절 결과는 실행마다 달라 1~3번 만들어 보라고 한다.
- 지시문 없는 복제는 목소리가 낮아지고(음색 유사도 하락) 평서문 끝이 크게 올라가 가장 나빴다.
- 표본이 작다(시드 1개, 4줄). 음높이 측정(pYIN)은 아주 높은 목소리에서 옥타브 오류가 날 수 있다. **어느 방식이 낫다고 할 근거가 부족하다** → 기본은 바꾸지 않는다.

들어 볼 수 있는 파일(작업 환경 임시 폴더): `scratchpad/prosody/{cont,ctrl,refe}-L{1,3,4,5}-s1.wav` (cont = 이어 말하기, ctrl = 조절 복제 + 지시문, refe = 지시문 없는 복제).

| `packages/video/src/timeline.ts` | `SceneTiming.mouth`, 단어 시간·입 기록을 실제로 잘린 프레임 기준으로 옮김 |

## 8. 남은 선택지 (사용자 결정)

| # | 선택지 | 근거 | 비용·위험 |
| --- | --- | --- | --- |
| A | **말투 지시문 켜기**: Modal `matlab-settings`에 `VOICESTUDIO_INSTRUCT` = `cheerful bright young female voice, natural conversational Korean intonation, statements end with a gentle fall` | 6장: 평서문 끝은 조금 낫고 의문문 올림은 약해짐 (갈림). 코드는 준비됨(비어 있으면 지금과 같음) | 모든 대사 음성을 새로 만든다(GPU 시간). 음색이 기준 녹음과 조금 달라질 수 있음. 먼저 한 콘텐츠로 들어 보고 결정 권장 |
| B | **기준 녹음을 평서문으로 끝나게 다시 고르기** (예: "…튀길까요? 오늘 같이 알아봐요.") | 이어 말하기는 기준 녹음의 리듬·감정을 잇는다(README). 지금 6개 기준 녹음은 모두 질문("튀길까요?")으로 끝난다 | 원칙 5: 목소리 = 저장소 기준 녹음 고정 → 기준 녹음 교체는 사용자 승인 필요. 목소리 이름(지문)이 바뀌어 음성을 모두 새로 만든다. 효과는 실험으로 확인해야 함 |
| C | 같은 대사를 2~3번 만들어 문장 끝 음높이로 고르기 | VoxCPM 문서: 결과가 실행마다 달라 1~3번 만들어 보라 | GPU 비용 2~3배. "평서문 끝이 오르면 다시"를 자동 검사로 넣을 수 있음 |
| D | 말 빠르기를 `atempo`(시간 늘이기) 대신 지시문("slightly faster")으로 | README 예: "(slightly faster, cheerful tone)". `atempo`는 WSOLA라 작은 배율에서는 대체로 괜찮지만 말소리가 뭉개진다는 보고도 있음. 지금 기본(보통)은 시간 늘이기를 하지 않음 | A와 같이 조절 복제가 되어야 함 |
| E | 대사 한 줄을 문장마다 따로 만들기 | 근거 약함: 우리 대사는 짧아(중앙값 39자) 긴 생성의 흐트러짐(#302)이 해당 없음. 조각마다 문장 끝 억양이 붙어 끊겨 들린다는 보고(#307) | 요청 수 2배, 이음새 |
| F | `VOICESTUDIO_SPEED`(기본 1.05) 정리 | VoxCPM2는 이 값을 쓰지 않는다 | 지금은 캐시 이름에만 쓰임. 바꾸면 음성을 모두 새로 만들게 되므로 그대로 둠 |

문장부호 정리(물음표·마침표 보장, 말줄임표 바꾸기)는 하지 않았다: 견본 83줄이 모두 문장부호로 끝났고, 말줄임표는 머뭇거림을 일부러 낸 자리라서다. 숫자·단위 읽기는 다른 작업(발음·글자 정리)의 범위다.
