## 3. 독립 코드 리뷰 (2026-11-03)

별도 리뷰 에이전트가 `studio-2.0..content-research` 변경을 검토했다. **치명적 문제 없음.** 승인 초기화, 승인 전 "검토" 문구 차단, 답변 수정 시 확인 해제는 모두 지켜짐을 확인했다. 지적 사항과 조치:

| 지적 | 조치 |
| --- | --- |
| 감각형 대본이 순서 7단계짜리 레시피를 "5단계면 끝"이라고 말함 | "핵심 5단계, 전체 과정은 블로그에"로 수정 + 테스트 |
| 기존 템플릿 영상(흔한 실수 있는 레시피)에도 효과음이 붙음 | 연출 엔진의 화면 연출·훅에만 효과음. 샘플 5개 템플릿 모두 효과음 없음 테스트 |
| 훅을 바꾸면 예전 훅 장면에 올린 클립이 새 훅에 붙음 / 새 대본 번호와 예전 클립이 엇갈림 | 새 훅 장면은 새 번호. 내용이 바뀐 장면의 클립 연결을 풀고 알림(파일은 보존) + API 테스트 |
| 12장면 대본에서 훅을 바꾸면 마지막 장면이 잘림 | 거절하고 안내 + 테스트 |
| 승인자가 이희재가 아니어도 "이희재 연구자가 검토" 표시 / 블로그 "OO 연구자가" 문구 | 승인자 이름이 이희재일 때만 그 문구, 아니면 "조리 정보 검토: (이름)". 블로그는 "(확인: 이름, 날짜)" + 테스트 |
| 빨간 오류가 있어도 블로그 "게시 준비 완료" | 일관성·문체 오류가 있으면 준비 아님 + API 테스트 |
| (제안) 실패 장면에 "설명용 연출" 표시 없음, 짧은 답("네")이 1인칭 문장 통과, 잘못된 style 값 | 모두 반영 |
| (제안, 미반영) 코미디형 둘째 장면은 훅을 결과 선공개로 바꾸면 어색함 | 훅 변경 시 연출과 맞는 훅을 쓰도록 대표 훅을 표시. 문장 자동 조정은 다음 단계 |
| (제안, 설계 선택) 연구자 답변 속 분량은 원본과 달라도 허용 | 연구자 본인 말이므로 허용. 단 원본과 충돌하면 사람이 판단 |

## 5. 남은 작업 (다음 순서)

1. **연구자 입력 반영 후 파일럿 재렌더** — A/B/C는 완료·실측됨(experiments.md 4절, 영상은 `out/pilot/`이라 Git 밖). 훅 단축 후 버전(A·C)은 아직 다시 렌더하지 않았다.
2. **사례 분석 보강** — reels-analysis.md (YouTube 영상 재생이 이 서버에서 막혀 메타데이터·썸네일·자동 프레임 수준). 사용자가 PC에서 직접 본 영상 메모를 받으면 "시청" 수준으로 올릴 수 있다.
3. **배경음악** — 효과음은 구현 완료. 배경음악은 라이선스가 확인된 음원만, 또는 앱에서 게시할 때 플랫폼 음악을 붙이는 방식 (editing-playbook 3절).
4. **맛조수 시리즈 장치** — 승급 서사·실험 노트 도장·회차 표시 (character-brand-guide 2절, 가설).
5. **훅 실험 기록** — 트라이얼 릴스 결과(건너뛰기 비율·평균 시청·보내기)를 입력해 다음 추천 이유에 반영.
6. **음성 답변 받아쓰기** — VoiceStudio 받아쓰기 모델 설치 후 전문가 답변을 말로 받기.
7. **AI 훅·대본 제안** — 유료 API 승인 후(스튜디오 2.0 2단계). 같은 검증(`hookLineIssues`, `checkScript`)을 거친다.
