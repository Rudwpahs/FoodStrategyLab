# 맛조수 캐릭터·이희재 브랜드 가이드

- 작성일: 2026-11-03
- 근거: [character-brand-research.md](character-brand-research.md) (사례·연구 S01~S43, 실험 E1~E8), [sources.md](sources.md) (F8·F9·F10)
- 이 문서는 **운영 기준**이다. 효과가 증명된 공식이 아니라, 근거를 바탕으로 정한 출발점이며 실험으로 고친다.

## 1. 핵심 문제와 방향

캐릭터가 인기를 얻으면 뒤에 있는 실제 전문가 이름은 묻히기 쉽다. Betty Crocker 같은 가상 인물이 실제 가정학자들을 가렸고, 유명 보증인이 오히려 브랜드 기억을 떨어뜨리는 "뱀파이어 효과"가 대규모 조사(4,970명)에서 보고됐다. 이 효과는 **보증인과 브랜드의 연결이 강할 때** 줄어든다 (research 1장).

→ 방향: **맛조수는 묻고, 이희재가 답한다.** 지식은 언제나 이희재 이름과 같은 화면에 놓는다.

## 2. 맛조수

| 항목 | 기준 |
| --- | --- |
| 한 문장 성격 | 궁금한 건 못 참고 일단 해 보다 꼭 한 번 허둥대지만, 선생님 팁 하나로 금세 눈이 반짝이는 연구소 조수 |
| 역할 | 시청자 대신 질문한다. **원리를 단정적으로 설명하지 않는다.** 전문 직함(기능장·연구자·전문가)을 쓰지 않는다 |
| 이희재를 부르는 말 | "희재 선생님!" (매 편 1~2회, 2회 이하) — 캐릭터의 습관으로 이름을 반복시킨다 (펭수가 "김명중!"을 외친 방식, [가설] E2) |
| 실수 | 허술함은 맛조수에게, 정확함은 이희재에게. 단 **무능한 실수의 반복은 호감을 깎을 수 있다**(프랫폴 효과) → 상황극 훅은 반복 방지 규칙으로 자주 쓰지 않는다. 위생·안전 실수는 웃음 소재로 쓰지 않는다 |
| 고정 의식 | 2~3개만, 표현은 돌려쓴다: ① 짧은 브랜드 문구 "이희재의 맛 연구소, 오늘의 실험!" ② "희재 선생님!" ③ 서명 카드 앞 마무리 인사 |
| 성장 | 견습 조수 → 정식 연구원 승급 서사, 실험 노트 도장, 회차 표시 [가설] — 아직 미구현 |
| 세계관 | 작게: 연구소(이희재 연구소장), 조수(맛조수), 실험 노트, 승급 시험. 설정은 이 문서로 고정 |
| 유머 | 그 편의 원리와 연결된 것만. 시청자나 실패작을 비웃지 않는다 |
| AI 공개 | 설명란에 "맛조수는 AI로 만든 캐릭터"를 밝힌다. 게시 문구에 이미 "AI 캐릭터 애니메이션, 음성은 AI 합성" 문구가 들어간다 |

### 대사 톤 예시 (호두정과)

| 좋음 | 피함 | 이유 |
| --- | --- | --- |
| "희재 선생님! 대체 왜 이렇게 된 거죠?" | "제가 알려 드릴게요, 이건 마이야르 반응이에요" | 맛조수는 지식의 주인이 아니다 |
| "이 한 단계에 비밀이 있대요" | "이게 정답입니다" | 들은 말을 전하는 조수 |
| "으악! 제 호두정과가 왜 이렇죠?" (가끔) | 매 편 실수로 시작 | 반복된 같은 결말은 YouTube 정책 위험(S17) + 프랫폴 |

## 3. 이희재 이름·전문성 노출

### 3.1 영상 안 노출 슬롯 (긴 경력 소개는 영상 밖으로)

| 슬롯 | 내용 | 코드 |
| --- | --- | --- |
| ① 오프닝 | 훅을 먼저, 둘째 장면에 브랜드 문구 1줄 (직함 없이) | `BRAND.shortOpening` — 연출 엔진이 훅 다음 장면에 넣는다 |
| ② 중간 | 원리 장면 "이희재 연구자의 조리 노트에 따르면…", 팁 장면 "조리기능장 이희재의 한 줄 팁" — 이름과 지식이 같은 화면 | `BRAND.notePhrase`, `BRAND.tipPhrase` |
| ③ 엔딩 | 서명 카드: 직함 2개(조리기능장 · 조리외식경영 연구자), 이름, 연구소 이름. 승인된 영상에만 "검토했습니다" | visual `signature` (`KitchenVideo.tsx` SignatureCard) |
| 호칭 | 코미디형: "희재 선생님!" | `styles.ts` comedy |
| 실물 증거 | 실제 완성 사진이 있으면 결과 공개 장면·팁 장면에 사용 | visual `result` + PhotoInset |

테스트로 확인하는 규칙: 연출 엔진 대본에 "이희재"가 반드시 나오고, "조리기능장"은 영상 대사에서 2회 이하 (`hooks.test.ts`).

### 3.2 영상 밖

- 채널·계정 이름은 **"이희재의 맛 연구소"** 유지. 맛조수 단독 계정은 만들지 않는다.
- 설명란: 2줄 고정 바이오 + 레시피 출처(강의 기관명) + 검수 상태.
- 경력은 자랑 대신 에피소드 소재로 ("강의에서 가장 많이 받은 질문"). 블로그 질문지에 "수업에서 자주 받는 질문"을 넣었다.
- 대표 레시피에만 "이희재표"를 붙인다 [가설] E7.

### 3.3 "검토·검증" 표기 규칙 (필수, 코드로 강제)

1. "이희재 연구자가 검토/검증" 표현은 **이희재가 승인한 그 대본 버전**으로 만든 결과물에만 쓴다.
2. 승인 뒤 대본·훅·장면을 바꾸면 새 버전이 되어 승인이 풀린다 (훅만 바꿔도 마찬가지 — API 테스트로 확인).
3. 블로그의 경험·의견 문장은 연구자 답변 원문만 쓰고, 답변은 **연구자 본인 확인**이 있어야 게시 준비 완료가 된다. 답을 고치면 확인이 풀린다.
4. 승인 전 SNS·블로그에 "검토한" 표현이 있으면 일관성 검사가 오류로 막는다.
5. 원리·팁 문장이 AI 초안이거나 "검수 필요" 표시가 있으면 연구자 확인 전에는 게시하지 않는다 (현재 호두정과·들깨파스타 샘플의 원리·팁 문장이 이 상태다).

## 4. 측정 (모두 가설, 자체 데이터와 소규모 설문만)

| ID | 무엇을 | 어떻게 |
| --- | --- | --- |
| E1 | 서명 위치 | 엔딩만 / 중간 카드 + 엔딩 / 오프닝 + 엔딩 — 서명 구간 이탈, 회상률 |
| E2 | 이름 전달 방식 | 자막만 / "희재 선생님!" 호칭 + 자막 / + 이희재 실제 음성 1문장(동의 시) |
| E3 | 24시간 뒤 회상 설문 | 지인·수강생 10~30명. 비보조 질문("팁을 준 사람은?")을 먼저, 그다음 보기(가상 이름 포함) |
| E4~E8 | 댓글 이름 언급, 실제 사진 엔딩, 실물 노트, "이희재표" 명명, 유입 경로 한 문항 | research 4장 |

판정: 같은 조건 3편 이상의 중앙값으로 **방향만** 본다. 통계적 유의성을 주장하지 않는다. 거짓 문구는 실험하지 않는다.
